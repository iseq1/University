# Подключение облачных LLM-шлюзов

## 1. Принцип интеграции

Генерация текста в Gamer Passport выполняется **только через HTTP API**. 
Проект не скачивает веса LLM, не запускает Ollama и не использует локальный Transformers pipeline.
Компьютер пользователя отправляет HTTPS-запрос шлюзу, а вычисления выполняются на стороне поставщика.

Поддерживаются три шлюза:

| Провайдер | Base URL | Протокол | Модель по умолчанию в `.env.example`                                                |
|-----------|---|---|-------------------------------------------------------------------------------------|
| Atria     | `https://api.atria-asi.ai/v1` | OpenAI Chat Completions | `Atria-Dawn`                                                                        |
| ShareLLM  | `https://sharellm.net/v1` | OpenAI Chat Completions | `deepseek-v4.1-flash` (пример; проверьте доступность/бесплатный маршрут в аккаунте) |
| GigaChat  | `https://api.giga.chat/v1` | OpenAI Chat Completions | `GigaChat-2` (пример; проверьте доступность/бесплатный маршрут в аккаунте)          |

У клиентов общий формат: `POST {BASE_URL}/chat/completions`, заголовок `Authorization: Bearer ...`, JSON `model` + `messages`. 
Для получения списка моделей можно попробовать `GET {BASE_URL}/models` с тем же Bearer-токеном. Список и идентификаторы моделей определяются самим шлюзом и могут меняться.

> **Важно о бесплатности и доступности из РФ.** Бесплатные квоты, перечень моделей, ограничения по регистрации и географии меняются.

> Документация сервисов сообщает о бесплатной квоте ShareLLM 120 запросов за 5 часов и 600 запросов в неделю и о большом списке моделей; это снимок состояния на момент проверки автором, а не гарантия постоянного тарифа. Текущая публичная страница ShareLLM одновременно описывает тарификацию по токенам и оплату за использование. Поэтому перед работой нужно проверить в личном кабинете, что выбран именно бесплатный маршрут/квота и что запрос не списывает платный баланс. 

> Для Atria статья сообщает о стартовом пакете токенов, но официальный сайт предупреждает об изменении/ужесточении квот; точный остаток проверяется в консоли. 

> Ни один из этих источников не даёт безусловной гарантии доступности из любой сети РФ: проверьте регистрацию и тестовый запрос из той сети, где будет запускаться приложение.

## 2. Вариант A — Atria

### Получение ключа

1. Откройте [Atria API](https://api.atria-asi.ai/).
2. Войдите в консоль доступным способом регистрации (на странице API описан вход через Google).
3. Перейдите в раздел API Keys.
4. Создайте новый ключ, задав понятное имя, например `gamer-passport-dev`.
5. Скопируйте ключ сразу: полный ключ отображается только при создании. Храните его в `.env`, не публикуйте в Git и не вставляйте во frontend.
6. В кабинете проверьте доступную квоту/лимиты и текущий идентификатор модели. В документации шлюза указан `Atria-Dawn`; прежний `Atria-Dawn-Preview` заявлен как совместимый, но для новой настройки используйте актуальное имя из каталога.

### Настройка проекта

В корневом `.env`:

```dotenv
LLM_PROVIDER=atria
LLM_TIMEOUT=120
ATRIA_API_KEY=вставьте_свой_ключ
ATRIA_BASE_URL=https://api.atria-asi.ai/v1
ATRIA_MODEL=Atria-Dawn
```

Если каталог/консоль показывает другое имя модели, укажите его в `ATRIA_MODEL`.

### Проверка ключа напрямую

```bash
curl https://api.atria-asi.ai/v1/chat/completions \
  -H "Authorization: Bearer $ATRIA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"Atria-Dawn","messages":[{"role":"user","content":"Ответь одним словом: работает"}],"stream":false}'
```

В Windows PowerShell сначала задайте переменную `$env:ATRIA_API_KEY="..."`, затем выполните аналогичный `curl.exe` запрос.

## 3. Вариант B — ShareLLM

### Получение ключа

1. Откройте [ShareLLM](https://sharellm.net/).
2. Зарегистрируйтесь и войдите в личный кабинет.
3. Откройте раздел API Keys / Start Using Models (названия элементов интерфейса могут изменяться).
4. Создайте API-ключ и сохраните его. Не передавайте его третьим лицам и не добавляйте в репозиторий.
5. В кабинете откройте каталог моделей и выберите модель/маршрут, явно отмеченный как Free, если такой маршрут доступен вашему аккаунту. Скопируйте точный `model id`.
6. Проверьте тариф и биллинг: не выбирайте платный маршрут и не включайте пополнение/платное списание, если требуется строго бесплатное использование. Бесплатные лимиты из статьи Habr (120 запросов/5 часов, 600/неделю) следует считать ориентиром из публикации, а не гарантированным текущим SLA.

### Настройка проекта

```dotenv
LLM_PROVIDER=sharellm
LLM_TIMEOUT=120
SHARELLM_API_KEY=вставьте_свой_ключ
SHARELLM_BASE_URL=https://sharellm.net/v1
SHARELLM_MODEL=точный_model_id_из_каталога
```

Значение `deepseek-v4.1-flash` в `.env.example` — пример из списка моделей, упомянутого в публикации; если в вашем кабинете оно отсутствует или не помечено Free, замените его.

### Проверка ключа и модели

```bash
curl https://sharellm.net/v1/models \
  -H "Authorization: Bearer $SHARELLM_API_KEY"
```

Затем проверьте Chat Completions:

```bash
curl https://sharellm.net/v1/chat/completions \
  -H "Authorization: Bearer $SHARELLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"ВАШ_MODEL_ID","messages":[{"role":"user","content":"Ответь одним словом: работает"}],"stream":false}'
```

## 4. Вариант C — GigaChat

### Получение ключа

1. [Зарегистрироваться в личном кабинете](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-create-project) и создать проект GigaChat API, который нужен для управления доступом к API и просмотру статистики.
2. [Покупать токены](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-tokens-purchase) для оплаты запросов к API (или использовать бесплатный пакет).
3. Для работы с GigaChat API [установите сертификаты НУЦ Минцифры](https://developers.sber.ru/docs/ru/gigachat/certificates).
4. [Делать простые запросы к API](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api) с помощью разных инструментов.

### Настройка проекта

```dotenv
LLM_PROVIDER=sber
LLM_TIMEOUT=120
SBER_AUTH_KEY=вставьте_свой_ключ
SBER_BASE_URL=https://api.giga.chat/v1
SBER_MODEL=точный_model_id_из_каталога
```

### Проверка ключа и модели

Получите токена доступа (аутентификация запроса)

```bash
curl -L -X POST 'https://ngw.devices.sberbank.ru:9443/api/v2/oauth' \
-H 'Content-Type: application/x-www-form-urlencoded' \
-H 'Accept: application/json' \
-H 'RqUID: <уникальный_идентификатор_запроса>' \
-H 'Authorization: Basic authorization_key' \
--data-urlencode 'scope=GIGACHAT_API_PERS'
```

Затем проверьте Chat Completions:

```bash
curl -L -X POST 'https://api.giga.chat/v1/chat/completions' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'Authorization: Bearer <токен_доступа>' \
--data-raw '{
  "model": "GigaChat",
  "messages": [
    {
      "role": "user",
      "content": "Привет! Как дела?"
    }
  ],
  "stream": false,
  "repetition_penalty": 1
}'
```


## 4. Запуск Gamer Passport

1. Скопируйте `.env.example` в `.env`.
2. Выберите **один** шлюз через `LLM_PROVIDER` и заполните только соответствующий ключ.
3. Укажите точный ID модели из личного кабинета.
4. Установите зависимости и запустите приложение:

```bash
poetry install
poetry run python run.py
```

5. Выполните сценарий, который вызывает `CriticAgent` или `EditorAgent`. Проверьте таблицу `llm_calls`: должны появиться провайдер, модель, статус и задержка. Содержимое промптов и ответов не записывается — сохраняются только их SHA-256 хеши.

## 5. Типовые ошибки

| HTTP/ошибка | Что проверить |
|---|---|
| `401` | Ключ скопирован полностью, не отозван, передаётся как Bearer |
| `403` | Доступ к API/модели разрешён тарифом и аккаунтом; возможны региональные ограничения |
| `404` | Base URL и путь `/chat/completions`; точный ID модели |
| `429` | Квота или лимит запросов исчерпаны; дождитесь сброса лимита |
| `402` | Платный баланс/тариф обязателен или бесплатная квота исчерпана; не продолжайте, если нужен только free-tier |
| Timeout / network error | DNS, VPN/прокси, доступность домена из вашей сети, состояние шлюза |

## 6. Безопасность

- `.env` находится в `.gitignore`; коммитьте только `.env.example` без секретов.
- Не передавайте ключ в Streamlit/frontend/browser. Вызов должен идти с backend.
- Не включайте автоматическое платное пополнение для проекта с требованием бесплатного тарифа.
- Не помещайте в промпты пароли, API-ключи, приватные данные и Steam-токены.
- Учитывайте, что промпты отправляются внешнему поставщику; передавайте только минимально необходимые игровые данные.

## 7. Источники и ограничения проверки

- [Habr: «Где ещё дают LLM API бесплатно: проверяю очередные находки»](https://habr.com/ru/articles/1085352/) — публикация содержит описанные автором бесплатные квоты и проверенные им модели.
- [Atria API](https://api.atria-asi.ai/) и [официальная документация Atria](https://api.atria-asi.ai/docs) — базовый URL, Bearer-аутентификация, Chat Completions и актуальное имя модели.
- [ShareLLM](https://sharellm.net/) — официальный сайт описывает единый OpenAI-compatible endpoint и модельный каталог; тарифы/стоимость нужно проверять в текущем личном кабинете.
- [GigaChat](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart) — документация быстрого старта для физических лиц. Описывает путь интеграции сервиса от А до Я.

Проверка сайта и документации не заменяет живой тест регистрации, сетевой доступности и бесплатной квоты из конкретной российской сети и аккаунта.
